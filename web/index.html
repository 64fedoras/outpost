Chat

Projects

A project keeps its files between tasks. Every task you start in it begins from the project's current files, and one task works in a project at a time (the rest wait). Optionally it clones a git repository and commits each finished round to a branch.

Planning

Claude

Claude plans tasks, writes anything the local models cannot, and fixes failing tests. Use a separate API key for Outpost and set a monthly limit on it in the Claude Console as a backstop.

When a subtask starts and two or more other nodes are idle with nothing waiting for them, up to two of them also write it. Copies that fail a quick syntax check are dropped and a judge node picks the best of the rest. Spare copies give up their node as soon as other work needs it. Local nodes only, so no Claude cost.

API keys

OpenRouter

Optional second cloud provider. Pick OpenRouter as the planner to plan, write what the nodes cannot, and fix failing tests with any model it offers. It shares the per-task spending cap above, using the cost OpenRouter reports for each call. Use a separate key and set a credit limit on it at openrouter.ai.

Hugging Face

Model settings

Idle unload

A node stops its model after it has served nothing for this long, to give back its RAM or VRAM. The next request loads it again, which takes as long as a normal load. Pooled models are never unloaded. Type a time such as 30s, 5m, 1hr or 2d, or 0 for never. Empty means 1 hour. Each node can override this on its card.

Pictures

Pictures made on the New image page are stored on this controller, never on the nodes. Old ones are deleted when they pass the age or the size limit below, whichever comes first. Pictures you mark Keep are never deleted automatically. Use 0 for no limit.

Wake sleeping nodes

Only nodes inside their working hours, with the task's label if it has one, and at most once every 10 minutes per node. A node card's Wake button sends the packet by hand. Wake-on-LAN must be turned on in the machine's firmware and network settings, and the controller must be on the same network (the packet is a broadcast and does not cross routers).

Free disk space

When a node has too little disk space for a model it is about to receive, it deletes stored models to make room: the least recently used first, and only as many as needed. Models this controller holds a copy of go first; only if that is not enough does it delete models a node downloaded straight from Hugging Face (they download again when needed). It never deletes the loaded model, one set to reload, or one being copied. If that still would not make room, nothing is deleted and the load fails with the usual disk space message. Each cleanup is noted on the node's card and in its log.

Command sandbox

How nodes run the commands tasks send them (tests, builds, fixes). Basic: a command can only change files in its own job folder, sees a cleaned-up environment and has no special rights; the network stays open. Strict: basic, with the network off unless the step downloads packages, and a deny list for dangerous system calls. Off: commands run with the node's own rights, as before. Linux nodes only for now; Windows and macOS nodes run commands unsandboxed. A node can override this on its card. If a build breaks and you suspect the sandbox, set it to Off to compare.

Project instructions

Standing rules (like CLAUDE.md) put at the top of every planner, worker, reviewer and fix prompt of tasks you create from now on. A file named OUTPOST.md at the root of a task's files is added too. Keep it short; it is cut at 8,000 characters.

Memory pooling

Off by default. Trusted home or lab networks only. Pooling lets nodes lend RAM and VRAM to a model on another node through llama.cpp's RPC mode. That traffic (model data and activations) crosses the LAN unencrypted, and the lending node has no authentication beyond allowing only the main node's IP address, which a hostile device on the same network can spoof. A lending node opens its pool port only while a pool is running and closes it when the pool ends. Turning pooling off dissolves every pool and unloads the pooled models.

A pool was already set up on this controller, so pooling was left switched on when you upgraded. Switch it off here if you no longer need it.

Kept in this browser only. On a phone, use the browser's Add to Home screen (Safari: Share → Add to Home Screen) to open Outpost like an app; with the controller's self-signed certificate, Chrome may only offer a bookmark-style shortcut.

Storage

How the controller's disk is used. Below 10% (or 5 GB) free, a warning shows at the top of every page and a disk low notification is sent.

Removes their per-round copies (so their rounds can no longer be undone), screenshots and the cached result zip (made again when you download). Conversations, files, attachments and the download itself stay. Runs once a day.

Updates from GitHub

Outpost can look at a GitHub repository's releases every 6 hours and download newer binaries for the controller and the platforms of your nodes. Each file is checked against the release's SHA256SUMS and must be an Outpost binary of that version before it is kept; it then appears in the Updates tab like an uploaded one. SHA256SUMS catches damaged downloads, not a tampered repository, since the releases are unsigned. Only the version check and downloads go to GitHub; nothing about your cluster is sent. Rollback works as before.

Whoever controls this repository can supply the code that runs on your controller and every node. Only enter a repository you own or fully trust.

Security and backup

Admin password

Locked out? On the controller run sudo outpost reset-password.

Sign-in security

HTTPS certificate

Upload a certificate chain and key (PEM), for example from your own CA or a Let's Encrypt DNS-01 certificate. Connected nodes are told the new fingerprint first, so they keep working.

Backup

One encrypted file with settings, the Claude key, node keys, the HTTPS certificate and all tasks. Restore on a fresh machine with outpost install controller --restore FILE. Keep the passphrase safe: it cannot be recovered.

Diagnostics

One zip to attach to a bug report: the controller's recent log, versions, node hardware and state, and the event logs of the 20 newest tasks. Keys, tokens, passwords and URLs are removed from the settings in it. Nothing is sent anywhere; the file downloads to this browser.

Leave without saving?

Add a node

Linux: installs a service that starts at boot and runs as the user who ran sudo. Windows: runs in the background with a tray icon and starts at sign-in. Each code works once and expires in 1 hour. Once a node joins with it, a new code appears here, so you can add the next node straight away.

Other ways: copy the binary yourself, or run over SSH

The node connects to . If that address is wrong, reinstall the controller with --advertise https://IP:8443.

Load a model on

Outpost installs llama.cpp on the node if needed, gets the model onto the node (from Hugging Face or the controller, depending on the model), and starts it. Large models take a while the first time.

2K128K

This model is a mixture of experts. Keeping the expert weights in system RAM leaves the GPU for attention and the context cache, so a model bigger than the GPU can still run quickly.

Pool memory from other nodes (for models too big for this one)

Helpers lend their RAM and VRAM over your network with llama.cpp's RPC mode; this node runs the model. Helpers stop their own model while lending, and only this node's address can connect to them. Expect slower generation over a home network: best for models that would not fit otherwise. Trusted networks only: pooling traffic is neither encrypted nor authenticated beyond that IP check.

Advanced

A small model of the same family (same tokenizer) guesses ahead and the main model checks its guesses: often 1.5 to 2 times faster for code on a GPU. Use a model under a fifth of the main one's size, for example a 0.5B or 1.5B of the same family. Watch the tok/s on the node card; if it is not faster, load again without it.

Clean up models on

Deletes the ticked models from this node's disk. The model that is loaded or set to load again after a restart is always kept. Copies on the controller and on other nodes are not touched; a node that needs a model again downloads it.

Load on…

Loading replaces any model the node has loaded. Need to pool memory or change context size? Use Load model… on the node's card.

Check cluster

A 16-token model call, an echo command and a connection to the file-sharing port on every online node, plus disk space, clock and version. Nothing is changed.

Working hours for 

    
Outside these hours the node takes no new work (a call already running finishes) and stops its model soon after, freeing the memory. Times are the controller's clock. An end time earlier than the start means the hours run past midnight.

    

    

    

    

  






  

    
Schedule 

    
A scheduled run starts on its own: the planner asks no questions and the plan is approved without you. It must plan on a node (never Claude or OpenRouter), so a schedule never spends money. A run is skipped while the previous one is still going, and you get the usual Finished or Failed notification.
